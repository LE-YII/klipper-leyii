# Klipper / Fluidd / KIAUH 改造需求与实施路线

## 项目目标

在保留 Klipper 现有运动控制实时性、配置语义和稳定性约束的前提下，改善打印机配置、调试、诊断和部署体验。重点是让用户能通过清晰的界面理解机器结构、验证接线/方向/运动学映射，并减少依赖命令行和猜测的操作。

本项目包含三个独立代码库，按各自上游维护，不将它们合并成一个仓库：

- `klipper-src/`：Klipper 主机端服务及必要时的 MCU 固件。上游当前检出 `master`；用户提到的目标分支名称为 `leyii`，创建前需确认准确拼写/大小写。
- `fluidd-src/`：Fluidd 网页前端及其 Moonraker 数据适配。
- `kiauh-src/`：KIAUH 安装管理脚本的中文化和安装/卸载体验改进。

## 设计约束

1. 保持 Klipper MCU 实时运动生成与主机职责边界；普通 UI 功能优先只改 Fluidd 或主机端工具。
2. 禁止让前端每次保存配置后直接对 MCU 热替换正在运行的运动模块。配置应用采用验证、受控重载、健康检查和可恢复的失败路径。
3. 运动诊断必须限幅、限速、禁止打印中启动，并清晰提示其是否会使坐标/归零状态失效。前端提示不能代替主机端校验。
4. 3D 中的绝对位置只在有可信归零/坐标状态时显示；未归零或单电机强制运动后应标记为未知。
5. 任何 MCU 固件刷写操作都应先识别目标设备、显示固件/连接信息并二次确认；动力电压检测若没有可靠硬件遥测，只能作为警告，不能宣称已互锁。
6. 所有诊断数据必须区分配置值、Klipper/Moonraker 报告值和物理传感器测量值，不能将估算值标成实测值。

## A. Klipper 主机端与固件

### A1. 配置应用与模块重载

- 保留现有配置文件作为底层/高级接口；UI 参数编辑器最终生成兼容的 Klipper 配置。
- 调研并实现配置校验、变更差异、受影响主机端对象/模块的依赖映射。
- 允许空闲状态下仅重载可安全重建的主机端模块；未知依赖、运动学/MCU/引脚/时钟等核心配置仍走完整 Klipper 重启。
- 提供重载结果、日志和恢复上一个有效配置的路径。不可承诺所有配置均能按模块重启。
- 目标体验：安全可重载的变更保存后约 1 秒内生效；需完整重启的变更要提前标明。

### A2. MCU 与硬件诊断能力

- 评估并暴露数字输入引脚原始状态/变化观察能力，以支持未正确配置上拉/下拉时的调试。显示 pin、MCU、采样时间和逻辑电平；不承诺模拟电压读数，除非硬件 ADC/接口明确支持。
- 评估 TMC UART/SPI 在线探测、寄存器读取和配置值/运行值差异报告。优先在空闲时执行低频、显式触发查询。
- 调研步进驱动器使能保持策略及 MCU/主机重启期间的行为；接受某些重启会丢失坐标，并确保 UI 将位置标为未知且要求重新归零。
- 如需激光测距或三轴振动传感器，先定义硬件接口、采样率、时序与传感器适配层；精度和用途按传感器能力披露。

### A3. 电机调试与运动学向导

- 单电机点动/识别：选择具体 stepper，使用固定、可配置但有严格上限的短行程和低速度测试方向、接线、rotation_distance。
- CoreXY 向导：分别测试 A/B 电机，执行 X/Y 正反向小位移，展示预期/实际运动方向，并生成 `dir_pin` 反相等配置建议。
- 多 Z 电机映射：把 `stepper_z`、`stepper_z1...` 与 3D 机架上的物理支点关联，协助验证 `z_positions` 或 QGL 点位顺序；不从名称臆测物理角点。
- Endstop 向导：实时显示输入触发变化，关联候选 pin 与轴，支持检查极性/上拉设置。
- 任何未归零的独立 FORCE_MOVE 测试之后，将 Klipper 运动学位置标记为无效，阻止普通坐标运动，要求归零或由用户执行明确的恢复流程。
- 所有动作禁止打印中运行；服务端验证最大距离/速度、对象存在、Klippy/MCU 在线和当前任务状态。优先结构化 API；首版可受控调用现有 `STEPPER_BUZZ`/`FORCE_MOVE`，但不得开放任意命令拼接。

### A4. 自动调节与振动优化（后续）

- 激光测距辅助轴向标定：记录命令移动量与传感器测量量，展示误差/重复性，不替代经过验证的位移传感器标定流程。
- 空闲时振动采集与静音参数建议：先只采集和报告，再考虑自动改参数；明确传感器位置、采样同步、运动激励和安全条件。
- 运行时电流/寄存器数据按驱动器型号及 Klipper/Moonraker 可用状态标识支持范围。

## B. Fluidd 前端

### B1. 参数化配置编辑器与历史

- 将常用配置转为有类型、范围、说明、依赖关系的 GUI 字段；高级用户仍可查看/编辑原始配置。
- 保存前展示 diff、校验问题、预计应用方式（模块级重载或完整重启），并提供撤销/历史版本。
- 记录修改时间、字段路径、前值/新值、来源和应用结果；敏感信息按需脱敏。

### B2. 交互式 3D 调试控制台

- 新增可独立懒加载的 Three.js 视图/仪表板卡片，模型资源和语义映射分离；支持旋转、缩放、点击部件查看配置和状态。
- 设备 manifest 使用稳定 ID 关联网格节点、stepper/TMC/endstop/config key；坐标标定文件单独保存，记录单位、轴映射、模型原点、行程和偏移。
- 第一版展示低面数框架、打印床、滑轨、工具头及电机位置；优先完成点击电机、Z 角点映射、CoreXY A/B 和小范围运动学测试。
- 读取 Klipper/Moonraker 的 toolhead 位置、归零状态、stepper_enable、configfile 与可用 TMC 状态；不每次状态变化重建场景，暂停不可见画布并限制移动端 DPR。
- 若打印机未归零、发生 FORCE_MOVE 或坐标可信度不足，显示相对/未知位置，不伪造绝对喷头轨迹。轨迹显示为有限长度、限采样的可选层。
- 3D 资产优先由 CAD 精确建模后，在 Blender 等工具整理网页低面数模型和显式线框/命名节点；第一阶段不开发 Fusion/SolidWorks 插件。

### B3. 状态与错误呈现

- 汇总 pin 输入变化、endstop、stepper/TMC 状态、MCU 与通信状态；区分缺失、未支持、离线和读取失败。
- 把常见错误转成包含对象名、配置段、执行命令/动作、日志引用和下一步检查项的诊断结果。
- 前端不能推断未由后端暴露的物理状态；实时电流、输入电压、原始 GPIO 等能力先按真实接口核验。

## C. KIAUH

- 将 KIAUH 主菜单、安装流程、更新/卸载、错误提示和帮助文本本地化为简体中文。
- 保持上游安装逻辑和依赖行为，中文化优先使用可维护的语言资源/翻译层，避免散落硬编码或改变脚本安全行为。
- 清楚展示将执行的安装、更新、卸载操作与目标路径；复用脚本现有确认和错误处理，不静默删除用户数据。
- 建立翻译术语表（Klipper、Moonraker、Fluidd、Mainsail、服务、组件、更新、卸载等），检查终端宽度、颜色和非交互环境回退。
- 评估是否向上游提交通用化语言支持；本项目分支单独维护中文翻译。

## 分阶段实施建议

### 阶段 0：Linux 环境和基线

- 固定 Linux 发行版/版本，确认 Python、编译工具、服务管理、串口与虚拟 MCU 测试环境。
- 三个仓库分别创建工作分支；Klipper 目标分支名 `leyii` 需确认后再创建。
- 保存上游 commit、运行现有测试、记录服务日志与构建步骤。

### 阶段 1：低风险可见成果

- KIAUH 中文化原型及翻译术语表。
- Fluidd 加入只读 3D 模型原型：旋转、部件拾取、步进器配置/状态面板。
- 3D 模型对 `z_positions`/QGL 点位提供可视化，不发送运动命令。

### 阶段 2：受控调试动作

- 先实现 endstop 实时状态与单步进器短行程测试，再加 CoreXY A/B 和 X/Y 方向向导、多 Z 电机映射确认。
- 在虚拟 MCU、台架和无负载实机上逐级验证限幅、打印中拒绝、动作终止、故障恢复及重新归零要求。

### 阶段 3：历史、诊断与配置应用

- 建立配置差异/历史、可读错误摘要、服务日志关联。
- 调研 Klipper 主机端对象依赖并实现有限模块重载；对无法证明安全的配置变更继续要求完整重启。

### 阶段 4：硬件扩展

- 按明确硬件清单接入 GPIO 输入观察、TMC 查询、激光测距、振动传感器及固件刷写工作流。
- 验证 CAN 两种拓扑（CAN MCU 直连、USB-CAN 适配器连接），报告内核/接口/设备枚举能力；“接口不可用”和“内核无 CAN 支持”分别诊断。
- 刷写页面识别进入 bootloader 的板卡、总线和目标固件；动力电压检测没有可靠硬件反馈时显示警示确认，不作为自动拒绝依据。

## 首批验收标准

- KIAUH 简体中文主流程可完成安装、更新和卸载，错误不会被翻译吞掉。
- Fluidd 3D 视图能将已配置 stepper 和 TMC 状态映射到可点击节点；未映射节点明确显示待确认。
- CoreXY 和多 Z 调试向导能给出预期运动与实测确认步骤；动作有严格限幅，打印中不可执行。
- 未归零的小电机测试不会让界面继续声称绝对位置可信；任何 FORCE_MOVE 后均要求重新归零或明确恢复。
- 所有暂未实现/硬件不支持的参数标记为“不可用/未提供”，不得以零值或推断值冒充。

## 当前待确认事项

- Klipper 分支名 `leyii` 是否准确；基于哪个 Klipper commit/上游分支。
- Linux 虚拟机发行版、版本、CPU 架构，以及是否需要直通 USB/串口/CAN 设备。
- 第一台测试机的运动学类型（Cartesian/CoreXY/其他）、主板型号、驱动器型号、限位/探针和传感器清单。
- Fluidd 目标以独立 fork 维护还是以插件/独立前端实现；KIAUH 是否计划提交上游。
